# Pimlico and Rhinestone

Import the provider subpath you need. Installing `@ensforge/hca` does not require both optional
provider peers. These integrations target the pinned account generation; provider service acceptance
and real sponsorship are [manual checks](/hca/release).

## Pimlico

```ts
import { pimlico } from "@ensforge/hca/pimlico";
import { sepoliaHcaDeployment } from "@ensforge/contracts/deployments";
import { createPimlicoClient } from "permissionless/clients/pimlico";
import { entryPoint07Address } from "viem/account-abstraction";
import { http } from "viem";
import { sepolia } from "viem/chains";

const execution = pimlico({
  profile: sepoliaHcaDeployment,
  chain: sepolia,
  owner,
  client: createPimlicoClient({
    chain: sepolia,
    transport: http(pimlicoRpcUrl),
    entryPoint: { address: entryPoint07Address, version: "0.7" },
  }),
  sponsorship: { policyId },
});
```

`owner` supplies `address` and `signMessage({ message })`. A Viem local account already implements
these; an injected wallet can provide a callback. `sponsorship` is optional: omit it for account-funded
execution, use `{}` for the client's default paymaster policy, or supply `policyId` and an optional
separate sponsorship client exposing `getPaymasterData`/`getPaymasterStubData`.

Sponsorship covers ETH gas, not the ENS registration price. Sponsorship failure never silently falls
back to spending HCA funds. The adapter supports deployed and counterfactual owner execution, not
sessions or cross-chain funding. `reviewLifetimeSeconds` limits local review validity; it is not an
on-chain expiry in the deployed owner validator. Review changed fees or sponsorship terms before
submitting again. Success is determined from the UserOperation outcome, not only the outer bundle receipt.

## Rhinestone

Apply the [required 1.8.0 compatibility patch](/hca/installation#rhinestone-compatibility-patch) before using this adapter.

```ts
import { rhinestone } from "@ensforge/hca/rhinestone";

const execution = rhinestone({
  profile: sepoliaHcaDeployment,
  chain: sepolia,
  owner,
  sessionSigner,
  sdk: { apiKey: rhinestoneApiKey },
});
const session = await execution.extensions.sessions.prepare(sdk.config, {
  hca,
  resolver,
  validUntil,
});
const enabled = await execution.extensions.sessions.enable(sdk.config, session);
await sdk.config.publicClient.waitForTransactionReceipt({ hash: enabled.hash });
```

Use a persistent session signer and stable session configuration to resume after restart. Store a
protected signer reference with registration; the storage payload does not contain the signer key.
`validUntil` is Unix time in seconds. Session preparation checks the deployed HCA generation and
builds constrained permissions for ENS registration and the selected resolver.

Destination execution is sponsored by default. Token-paid, unsponsored Rhinestone execution is
not supported for this release: hosted quotes currently contain additional funding or approval
requirements that the adapter rejects before signing. Increasing a balance or refund cap does not
resolve this route incompatibility. Do not confuse destination execution sponsorship with source-chain
funding fees. `sessionSalt`, `policy`, `sponsored` and `crossChain` are optional adapter configuration.

Pass the enabled permission ID and confirmed enable transaction hash when starting registration.
Use `revokeHcaSessions({ hca })` for destination revocation; cancelling a local registration does not
revoke an enabled session. Session renewal or replacement is an explicit authorization change through
`resumeHcaRegistration`, not a silent rebinding to a different signer.

Follow [Execute with Pimlico](/hca/guides/pimlico) or [Rhinestone Sessions](/hca/guides/rhinestone)
for a step-by-step record update.
