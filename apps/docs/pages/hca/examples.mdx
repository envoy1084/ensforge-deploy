# Examples

Examples live in `apps/docs/examples/hca` and are included in the docs TypeScript check. The interactive
playgrounds on individual read-action pages contains only read actions. Write examples are standalone source files
that run only when you invoke them.

## Local owner execution

From the repository root, with Docker running:

```sh
pnpm install
pnpm --filter @ensforge/test-env... build
pnpm --filter @ensforge/sdk... build
pnpm --filter @ensforge/docs example:hca:local
```

[`local.ts`](https://github.com/thenamespace/ensforge/blob/feat/hca/apps/docs/examples/hca/local.ts)
starts the pinned devnet, executes an owner call, and demonstrates registration ID/secret recovery
using config storage and a fresh SDK instance. Its container is disposed when the script exits.
It uses only local development accounts and does not contact a hosted bundler or paymaster.

## Provider registration

The following scripts submit **Sepolia writes when you run them**. They are integration examples. Separate manual runs have verified the supported provider paths
described in [Compatibility](/hca/compatibility); validate your own configuration before release.

Create `apps/docs/.env.hca` with your own values. It is ignored by Git:

```sh
SEPOLIA_RPC_URL=
HCA_OWNER_PRIVATE_KEY=
HCA_RESOLVER=
HCA_PAYMENT_TOKEN=
HCA_REGISTRATION_NAME=
HCA_MAX_REGISTRATION_PRICE=
HCA_MAX_EXECUTION_FEE=

PIMLICO_RPC_URL=
PIMLICO_SPONSORED=true
PIMLICO_POLICY_ID=

RHINESTONE_API_KEY=
HCA_SESSION_PRIVATE_KEY=
HCA_SESSION_VALID_UNTIL=
HCA_SESSION_ENABLE_HASH=
```

Use a test-only funded owner account. Resolver and payment-token addresses must match the recorded
Sepolia deployment and required permissions. Price/fee limits are integer base units; the session
expiry is a fixed Unix timestamp in seconds. Sponsorship covers execution gas, not the registration
payment token or the separate owner deployment/session-enablement transactions.

```sh
pnpm --filter @ensforge/hca... build
pnpm --filter @ensforge/docs example:hca:pimlico
# or
pnpm --filter @ensforge/docs example:hca:rhinestone
```

[`pimlico.ts`](https://github.com/thenamespace/ensforge/blob/feat/hca/apps/docs/examples/hca/pimlico.ts)
uses `permissionless` with EntryPoint 0.7 and optional sponsorship.
[`rhinestone.ts`](https://github.com/thenamespace/ensforge/blob/feat/hca/apps/docs/examples/hca/rhinestone.ts)
first enables a session and prints its public enable transaction hash. Save that hash as
`HCA_SESSION_ENABLE_HASH`, keep the same signer and expiry, then run again to register.

Both use [`sqlite-storage.ts`](https://github.com/thenamespace/ensforge/blob/feat/hca/apps/docs/examples/hca/sqlite-storage.ts)
with Node's built-in SQLite module and save state under `apps/docs/.ensforge/hca-example`.
The shared runner waits for receipts/commitment age for up to 15 minutes and returns on funding,
review or authorization requirements. Rerun with unchanged inputs to recover unfinished work.
Changing limits requires explicit `resumeHcaRegistration({ id, limits, execution })`; changing start
inputs can select a different workflow. Never delete the database after an ambiguous broadcast.
Do not rerun a completed implicit operation expecting it to select its old ID.

## Browser and server examples

- [`browser.tsx`](https://github.com/thenamespace/ensforge/blob/feat/hca/apps/docs/examples/hca/browser.tsx): import `HcaRegistrationExample` into your React application and supply config plus registration inputs. It uses the provider’s default IndexedDB storage and separates local interruption from cancellation. After reload, recover with unchanged inputs.
- [`remote.ts`](https://github.com/thenamespace/ensforge/blob/feat/hca/apps/docs/examples/hca/remote.ts): Web Request/Response endpoint factory and browser transport. Supply real authentication, operation authorization and a server-only signer resolver.
- [`funding.ts`](https://github.com/thenamespace/ensforge/blob/feat/hca/apps/docs/examples/hca/funding.ts): import `fundHca` with an adapter containing a reviewed route manifest, source wallet and quote inputs. It confirms ordered approvals and waits for destination funding. No route or hosted settlement is assumed.

These exported examples are integration modules for your app. They do not start a public server,
create provider credentials or choose a cross-chain route on your behalf.
